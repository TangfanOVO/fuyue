# 可选能力的分层装配

赴约公开版分成“家本身”和“按需能力”。用户不需要为了一个旅行房、记忆引擎或共读器接受整座屎山，也不需要因为只会用手机就被迫理解所有 API。

## 六种选择

| 选择 | 适合谁 | 公开版做什么 |
| --- | --- | --- |
| 不要前端，直接隐藏 | 只想聊天和保存资料 | 立即从首页、书房、房间和全部功能撤掉入口；不删现有资料 |
| 使用本地实现 | 功能已随公开包完整提供 | 直接启用 LocalData 实现 |
| 只拿前端 | 喜欢赴约的漂浮物、交互、叠叠卡或面板 | 给出独立包和契约，后端由采用者实现 |
| 接自己的后端 | 已有服务器或准备自己写 | 给出 required / optional routes 与验收清单 |
| 接现成协议服务 | 只用手机或不想运维 | 连接实现同一公开协议的服务，密钥与计量留在服务端 |
| 使用原项目 | 想看原作、替换赴约实现，或功能受许可边界无法内置 | 展示上游与许可证；它是来源和替代选择，不抢占已内置实现的默认位置 |

## 立即启用、隐藏与装配单

已经随公开包完整提供的 LocalData 能力，选择“直接用内置实现”后原地启用，不生成工作项，也不要求使用者再安装一遍。选择“去原仓库”会直接打开已登记的上游来源，不伪造本地安装结果。选择“完全隐藏”只改界面可见性，不生成装配单、不写共同工作本，也不删除以前的资料。唯一始终保留的恢复入口是“功能包”本身。

只有“只拿前端积木”“接自己的后端”或“使用现成协议服务”等确实还需要施工的选择，才会生成 `fuyue-build-plan` JSON，并把同一份计划写进共同工作本。装配单至少包含：

- `capabilityId` 与所属包；
- 建议仓库相对路径 `extensions/<capability-id>/`；
- 上游 URL 与许可证；
- 依赖能力；
- 必须与可选接口；
- 入口、返回、空态、权限、隐私和真数据验收清单。

手机 PWA / APK 只为尚未内置的外部实现生成计划与可下载文件。真正创建目录、安装依赖、拉取仓库和执行测试由桌面 CLI、Codex 或使用者自己的流水线完成，界面不能谎称手机已经完成了这些操作。已带入源码、通过自动测试且许可兼容的实现才标成“内置可用”；只有开放契约不等于后端已完成。

## 开放许可证怎样进入内置

MIT / ISC 等允许再发布的已有实现，赴约的产品目标是带入公开包并默认可用，而不是永久把采用者送去原仓库。带入时仍要保留原通知，处理依赖、数据权限和移动端运行，并在干净环境验收。图标几何、环境效果、颜文字、记忆账本与记忆星图直接随包提供；Engawa 现已带固定版本、回环侧车安装器、relay 白名单和前端，Journey Cards 则以内置纯文字 LocalData 手记落地。两者都保留 MIT 通知和上游入口。

共读与共听是另一种情况：赴约自己的使用需求很轻，现有实现不值得包装成满血版。公开包保留自己的前端供外观复用，同时分别推荐 Readest 与 music-together；这两个上游没有被复制进赴约运行时，也不会让赴约接管网易云账号或 Cookie。

CC BY-NC、PolyForm Noncommercial 等非商业边界的功能不并入 AGPL 核心；界面只提供来源和按需适配说明。这样既让懒人能看见我们已验证的魔改，也让想抄原作业的人总能回到原作者，并且不会把受限源码混进一键安装包。

## 后端边界

- 现成协议服务只是其中一种选择，不是所有空态的默认去向；它表示另一套后端实现同一接口，不表示聊天记录必须离开 LocalData。
- 模型连接、设备权限、媒体来源、日历来源和功能包安装是五类不同任务。
